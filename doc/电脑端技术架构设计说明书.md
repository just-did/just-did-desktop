## 2. 四层架构边界定义

```
依赖方向（自上而下，上层依赖下层，严禁反向）：

  ┌──────┐
  │  ui  │  QML 界面 + ViewModel + Model
  └──┬───┘
     │ 依赖（ui 只和 service 对话，不跳过 service 直接调 core）
  ┌──▼──────────┐
  │   service   │  业务服务层（统一入口）
  │ ReportService│  • 本地日报操作（记录、查看、清空、统计、备份）
  │ SyncService │  • 同步操作（submit、fetch、connect、health）
  │ HttpServer  │  • HTTP 适配（路由、请求解析、响应构造）
  └──┬──────────┘
     │ 依赖
  ┌──▼─────┐
  │  core  │  基础设施层（不关心业务，只提供数据存取和通用能力）
  └──┬─────┘  AppCore + DataManager + FileManager + DatabaseManager
     │ 依赖   + ConfigManager + LogManager + ConnectionStateMachine
  ┌──▼────┐
  │common │  数据结构 + 常量 + 错误码（零依赖）
  └───────┘
```

**核心原则：ui 只知道 service，不知道 core 的存在。** ui 的所有操作——无论是点"提交"记录一条日报，还是点"启动"开启 HTTP 服务——都通过 service 层的某个服务类完成。service 是 ui 的"唯一对话方"。

每一层都有严格的边界约束。违反边界的行为（如 core 引用 QML 类型、ui 直接调 DataManager）被视为架构违规，必须在 Code Review 中拦截。

### 2.1 common 层 — 共享基础

| 维度 | 定义 |
|------|------|
| **职责** | 定义全项目共享的**纯数据结构**、**常量**和**错误码枚举**。不包含任何行为逻辑。 |
| **允许的依赖** | 仅 Qt6::Core（`QString`、`QList`、`QDate`、`QMap` 等基础类型）。**不依赖 yaml-cpp、Qt SQL、Qt Quick 等任何其他库。** |
| **被谁依赖** | core、service、ui 均可自由依赖 common |
| **对外暴露** | 3 个头文件：`Types.h`、`Constants.h`、`ErrorCode.h`（仅头文件库，无需编译 .cpp） |

#### 边界约束

| # | 规则 | 反例（禁止） |
|---|------|-------------|
| C1 | **只能定义 struct / enum / constexpr，不得包含行为方法** | `struct DailyRecord { void save(); };` ❌ |
| C2 | **不得包含任何 I/O 操作**（文件、网络、数据库） | `void loadFromFile(QString path);` ❌ |
| C3 | **不得 include 本项目的其他层** | `#include "core/DataManager.h"` ❌ |
| C4 | **不得依赖 Qt Quick / Widgets / Sql / Network 模块** | `#include <QSqlDatabase>` ❌ |
| C5 | **数据结构中不得持有指针或引用到其他层的类型** | `QObject *owner;` ❌（引入了信号槽依赖） |
| C6 | **常量不包含业务逻辑判断** | `if (day > MAX_FETCH_FILES) return false;` ❌（这是 core/service 的事） |

#### 为什么需要这一层

打个比方：common 层相当于建筑工地的**标准件仓库**——砖的尺寸、钢筋的标号、螺丝的规格。所有工位都用同一套标准，但标准件本身不干活。如果每层各自定义 `DailyRecord`，service 传给 ui 时就要做转换，凭空多出胶水代码和出 bug 的机会。

### 2.2 core 层 — 核心业务逻辑

| 维度 | 定义 |
|------|------|
| **职责** | 实现所有**与 UI 和网络无关的核心业务逻辑**：数据持久化（文件 + SQLite）、配置管理、日志管理、连接状态机、乐观锁协调。 |
| **允许的依赖** | common、Qt6::Core、Qt6::Sql、yaml-cpp |
| **被谁依赖** | 仅 service 层 |
| **对外暴露** | 7 个头文件（见 3. 源码目录结构），编译为静态库 `justdid_core` |

#### 核心类清单

| 类 | 一句话职责 | 关键约束 |
|----|-----------|---------|
| `AppCore` | 应用生命周期总管，各模块初始化和销毁的协调者 | 单例。不持有 UI 引用。 |
| `ConfigManager` | YAML 配置文件读写 | 内部加锁，可跨线程调用。 |
| `LogManager` | 线程安全日志写入 + 文件滚动 | 单例。全局唯一写入口。 |
| `DatabaseManager` | SQLite CRUD（两张表的增删改查） | 不解析文件内容，不关心 DailyRecord 的业务含义。 |
| `FileManager` | 日报文件读写 + 乐观锁 + 原子写入 + .tmp 恢复 | 不碰 SQLite，不知道索引表的存在。 |
| `DataManager` | 外观模式：协调 FileManager + DatabaseManager，对外提供统一的数据接口 | 本层唯一对外暴露的数据入口。ui 和 service 只通过它操作数据。 |
| `ConnectionStateMachine` | 连接状态维护 + 心跳超时管理 | 不关心 HTTP 协议细节，只管状态转移逻辑。 |

#### 边界约束

| # | 规则 | 反例（禁止） |
|---|------|-------------|
| CO1 | **不得依赖 ui 层或 service 层** | `#include "ui/viewmodels/CalendarViewModel.h"` ❌ |
| CO2 | **不得包含任何 UI 相关代码**（QML、QQuickItem、widget 等） | `#include <QQuickItem>` ❌ |
| CO3 | **不得 include Qt HttpServer 或 Qt Network** | `#include <QHttpServer>` ❌ |
| CO4 | **不得直接操作 QML Context 或注册 QML 类型** | `qmlRegisterType<DataManager>();` ❌ |
| CO5 | **FileManager 不得直接写 SQLite**（反之 DatabaseManager 不知 DailyRecord 格式） | FileManager 中写 `INSERT INTO pc_daliy_report_index` ❌ |
| CO6 | **DatabaseManager 不解析 .txt 文件内容** | DatabaseManager 中读 `data/07/23.txt` ❌ |
| CO7 | **AppCore 不得直接访问下层模块的内部实现**（必须通过公开接口） | `AppCore::init()` 中直接 `QFile file("data/...");` ❌ |
| CO8 | **对外暴露的类不得将内部实现细节写入公共头文件** | 头文件中 `#include "DatabaseManager.h"`（如果只是内部使用，用前向声明） |

#### 内部协作关系

```
AppCore（总管）
  │
  ├── 持有 ──► ConfigManager
  ├── 持有 ──► LogManager
  │
  └── 持有 ──► DataManager（外观）
                  │
                  ├── 委托 ──► FileManager       （文件读写，不知道索引表）
                  └── 委托 ──► DatabaseManager   （索引 CRUD，不知道文件格式）
                                  │
                                  └── 独立的 SQLite 连接

ConnectionStateMachine（独立，仅被 AppCore 持有）
  └── 仅与 AppCore 交互，不碰数据层
```

### 2.3 service 层 — 业务服务

service 层是 ui 层的**唯一对话方**。ui 所有的操作——本地记录、查看日报、清空日期、备份恢复、启动 HTTP 服务、处理同步——都通过 service 层的某个服务类完成。service 不关心这些操作最终是走文件系统、SQLite 还是网络，它只负责编排业务流程，把数据存取委托给 core 层。

| 维度 | 定义 |
|------|------|
| **职责** | 为 ui 层提供**全部业务操作接口**：本地日报操作 + 手机同步操作 + HTTP 服务生命周期管理。不区分"网络服务"和"本地服务"——对 ui 来说都是"一个操作，调用 service，得到结果"。 |
| **允许的依赖** | common、core、Qt6::Core、Qt6::Network、Qt6::HttpServer |
| **被谁依赖** | 仅 ui 层 |
| **对外暴露** | 3 个头文件（`ReportService.h`、`SyncService.h`、`HttpServer.h`），编译为静态库 `justdid_service` |

#### 核心类清单

| 类 | 一句话职责 | 需要网络？ | 关键约束 |
|----|-----------|-----------|---------|
| `ReportService` | 本地日报操作：记录、查看、清空、统计、备份、恢复 | **否** | 不碰 HTTP。操作通过 DataManager 完成。 |
| `SyncService` | 同步业务逻辑：submit 请求体解析、fetch 响应组装 | **否**（本身是纯逻辑） | 无状态，不持有数据库连接，不碰 HTTP Header。 |
| `HttpServer` | HTTP 适配：TCP 监听、路由分发、Header/Body 解析、状态码设置 | **是** | 不包含业务逻辑。提取请求参数后委托给 SyncService 或 ReportService。 |

#### 类的协作关系

```
ui 层（ViewModel）
  │
  ├─ 本地记录 ──────► ReportService::addRecord() ──► DataManager（core）
  ├─ 查看日历 ──────► ReportService::getMonthIndex() ──► DataManager
  ├─ 清空日期 ──────► ReportService::clearDate()
  ├─ 备份恢复 ──────► ReportService::backup() / restore()
  │
  ├─ 启动服务 ──────► HttpServer::start() ──► 内部调用 SyncService
  ├─ 连接状态 ──────► ConnectionStateMachine（通过 AppCore）
  │
  └─（手机端请求到达时）
       HttpServer 路由 ──► 提取参数 ──► SyncService::submit() / fetch()
                              │
                              └──► DataManager（core）
```

**关键设计**：本地操作（ReportService）和网络同步（SyncService）都在 service 层，但它们是**独立的类**。ReportService 不需要 Qt Network 模块，SyncService 不需要了解 HTTP 协议细节。HttpServer 是这两者之间的桥梁——对手机端请求，HttpServer 提取参数后调 SyncService；对本地操作，ViewModel 直接调 ReportService。

#### 边界约束

| # | 规则 | 反例（禁止） |
|---|------|-------------|
| S1 | **不得依赖 ui 层** | `#include "ui/viewmodels/..."` ❌ |
| S2 | **不得包含任何 UI 代码**（QML、View、QQuickItem） | `#include <QQuickItem>` ❌ |
| S3 | **HttpServer 不得包含业务逻辑**（只做路由 + 参数提取 + 响应构造） | HttpServer 中写 `QFile file("data/07/23.txt");` ❌ |
| S4 | **SyncService 不得直接操作 HTTP 层**（不读 Header、不设 StatusCode、不碰 QHttpServerRequest） | SyncService 中写 `request.header("X-Batch-ID")` ❌ |
| S5 | **所有 service 类不得直接写文件或 SQLite**（必须通过 DataManager） | Service 类中写 `QSqlQuery query;` ❌ |
| S6 | **不得在 service 层初始化或持有 core 层的模块**（应通过 AppCore 注入） | Service 构造函数中 `new DatabaseManager()` ❌ |
| S7 | **ReportService 不得依赖 Qt Network / HttpServer 模块** | `#include <QHttpServer>` ❌ |

#### HttpServer 与 SyncService 的职责分割

这是最容易越界的边界，单独强调：

```
HttpServer（适配层）                    SyncService（业务层）
─────────────────                     ────────────────
• 从 Header 提取 X-Batch-ID     →    接收 batchId 参数（纯 QString）
• 读取 Request Body             →    接收 QByteArray 参数
• 解析 JSON 请求体格式           →    接收解析后的 QJsonObject
• 设置 HTTP Status Code         →    只返回业务结果（QJsonObject / QByteArray）
• 设置 Content-Type             →    只返回数据类型标记（enum）
• 调用 ConnectionStateMachine   →    不知道状态机的存在
```

**反例**：如果 SyncService 直接读了 `X-Batch-ID` Header，那么未来写单元测试时就必须构造 HttpServer 的请求对象——SyncService 和 HTTP 协议耦合了。正确做法是 HttpServer 提取 batchId 后以 `QString` 传入 SyncService，SyncService 的单元测试只需要传一个字符串。

### 2.4 ui 层 — 用户界面

| 维度 | 定义 |
|------|------|
| **职责** | QML 界面渲染、系统托盘管理、ViewModel（C++ 桥接 QML 与 service 层）、QAbstractListModel 子类（列表数据适配）、用户交互响应。 |
| **允许的依赖** | common、service（通过 AppCore 获取 service 实例）、Qt6::Core、Qt6::Quick、Qt6::Gui |
| **被谁依赖** | 不被任何其他层依赖（顶层） |
| **对外暴露** | C++ 侧编译为静态库 `justdid_ui`；QML 侧通过 `.qrc` 或文件系统加载 |

#### 核心类清单

| 类 | 一句话职责 | 关键约束 |
|----|-----------|---------|
| `CalendarViewModel` | 月份日历数据（哪些日期有日报）+ 翻月操作 | 通过 ReportService 获取索引数据。 |
| `TimelineViewModel` | 单日记录列表 + 选中日期 + 清空操作 | 通过 ReportService 操作。 |
| `FloatingInputViewModel` | 悬浮窗输入内容 + 提交记录 + 展开/收起状态 | 通过 ReportService 提交记录。 |
| `StorageViewModel` | 存储概览统计 + 清理/备份/恢复操作入口 | 通过 ReportService 操作，重 I/O 提交到工作线程。 |
| `ConnectionViewModel` | 连接状态展示 + 启动/停止/设置端口 | 通过 SyncService / HttpServer（由 AppCore 提供）操作。 |
| `CalendarModel` | QAbstractListModel：月份日期格子数据 | 纯数据适配，不包含业务逻辑。 |
| `RecordListModel` | QAbstractListModel：单日记录列表 | 同上。 |

#### 边界约束

| # | 规则 | 反例（禁止） |
|---|------|-------------|
| U1 | **QML 文件不得直接调用 C++ 业务对象的方法**（只能通过 ViewModel） | QML 中 `ReportService.addRecord(...)` ❌ |
| U2 | **ViewModel 不得直接操作 SQLite、文件系统或 DataManager**（必须通过 service 层的 ReportService 或 SyncService） | ViewModel 中 `QSqlQuery query;` ❌；ViewModel 中 `#include "core/DataManager.h"` ❌ |
| U3 | **ViewModel 不得直接操作 HTTP 对象**（必须通过 AppCore 获取 service 实例） | ViewModel 中 `m_httpServer->start();` ❌ |
| U4 | **QML 不得包含 if/else 业务分支逻辑**（业务判断在 ViewModel 中） | QML 中根据 `code === -4` 决定重试 ❌（应由 ViewModel 处理并设置 `errorMessage` 属性） |
| U5 | **Model 类只做数据适配，不执行业务操作** | `CalendarModel::data()` 中调用 `DataManager::getRecords()` ❌ |
| U6 | **ViewModel 不得持有 QQmlApplicationEngine 或 QQuickItem 引用** | `m_rootObject = engine->rootObjects().first();` ❌ |
| U7 | **悬浮窗和管理窗口的状态同步必须通过 AppCore，不直接互相引用** | `FloatingInputViewModel` 中持有 `MainWindow *` ❌ |

#### QML 和 C++ 的边界

```
┌──────────────────────────────────────────────────────┐
│                    QML 世界（声明式）                   │
│                                                      │
│  负责：布局、动画、颜色、字体、用户手势                  │
│                                                      │
│  允许的逻辑：                                          │
│    • visible: connectionState === 2  （简单状态映射）   │
│    • color: hasContent ? "blue" : "gray"             │
│    • onClicked: viewModel.submit()  （调用 VM 方法）   │
│                                                      │
│  不允许的逻辑：                                        │
│    • if (response.code === -4) retryTimer.start()    │
│    • for (var i = 0; i < records.count; i++) { ... } │
│    • Qt.createComponent("ErrorDialog.qml")            │
├───────────────────────────────────────────────────────┤
│                   C++ 世界（命令式）                    │
│                                                      │
│  ViewModel：                                          │
│    • 接收 QML 调用 → 委托给 service 层 → 更新 Q_PROPERTY │
│    • 处理业务错误（如 code=-4 → 自动重试逻辑）          │
│    • 管理异步操作的生命周期（QFutureWatcher）            │
│                                                      │
│  Model (QAbstractListModel)：                         │
│    • 纯数据容器 + 变更通知                              │
│    • 不执行业务逻辑                                    │
└──────────────────────────────────────────────────────┘
```


### 2.6 编译时边界检查

通过 CMake 的 `target_link_libraries` 强制依赖方向：

```cmake
# common — 零内部依赖
target_link_libraries(justdid_common PUBLIC Qt6::Core)

# core — 仅依赖 common
target_link_libraries(justdid_core PUBLIC justdid_common Qt6::Core Qt6::Sql yaml-cpp::yaml-cpp)

# service — 依赖 core + common，不依赖 ui
target_link_libraries(justdid_service PUBLIC justdid_core Qt6::Core Qt6::Network Qt6::HttpServer)

# ui — 只依赖 service + common，不直接依赖 core
# (common 通过 service 传递，但显式列出以使用其类型)
target_link_libraries(justdid_ui PUBLIC justdid_service Qt6::Core Qt6::Quick Qt6::Gui)
```

如果 core 层误写了 `#include <QQuickItem>`，编译会失败（因为 `justdid_core` 没有链接 `Qt6::Quick`）。CMake 的 link 依赖即编译时的边界卫士。

## 3. 源码目录结构

```
src/
├── CMakeLists.txt                # 顶层构建（聚合子目录 + 最终可执行文件）
├── main.cpp                      # 入口：初始化 AppCore → 启动 QML 引擎
│
├── common/                       # 共享层（无外部依赖）
│   ├── CMakeLists.txt
│   ├── Types.h                   # 核心数据结构（DailyRecord, IndexEntry, BatchInfo ...）
│   ├── Constants.h               # 常量（默认端口、心跳间隔、文件上限 ...）
│   └── ErrorCode.h               # 错误码枚举 + 错误消息映射
│
├── core/                         # 核心逻辑层（依赖 common，不依赖 UI）
│   ├── CMakeLists.txt
│   ├── AppCore.h / .cpp          # 应用生命周期总管（单例）
│   ├── ConfigManager.h / .cpp    # YAML 配置读写
│   ├── LogManager.h / .cpp       # 线程安全日志管理器（单例）
│   ├── DatabaseManager.h / .cpp  # SQLite 操作封装
│   ├── FileManager.h / .cpp      # 文件读写 + 乐观锁
│   ├── DataManager.h / .cpp      # 外观：对外统一数据接口
│   └── ConnectionStateMachine.h / .cpp  # 连接状态机
│
```

## 4. 线程模型

```
┌─────────────────────────────────────────────────────┐
│                    主线程 (GUI Thread)                │
│                                                     │
│  QML Engine  ←──  ViewModels  ──→  AppCore         │
│       │              │                  │            │
│       │         signals/slots     ┌─────┴──────┐    │
│       │         (direct conn)     │            │    │
│       ▼                           ▼            ▼    │
│  [QML Views]              SyncService    HttpServer │
│                           DataManager   (async I/O) │
│                                                     │
│  注：HttpServer 使用 Qt HttpServer 异步 API，       │
│  不需要独立线程。轻量 SQLite 查询在主线程执行。      │
└─────────────────────────────────────────────────────┘
                              │
                              │ QThreadPool::globalInstance()
                              ▼
┌─────────────────────────────────────────────────────┐
│                工作线程池 (Worker Threads)            │
│                                                     │
│  处理重 I/O 操作：                                   │
│  • ZIP 压缩（/sync/fetch 多文件响应）                 │
│  • 备份导出（大日期范围 ZIP）                         │
│  • 备份恢复（ZIP 解压 + 索引重建）                    │
│                                                     │
│  通过 QtConcurrent::run() 提交任务，                 │
│  结果通过 QFutureWatcher + 信号回传主线程。           │
└─────────────────────────────────────────────────────┘
```

### 线程安全要点

| 资源 | 访问方式 |
|------|---------|
| SQLite 连接 | 仅主线程使用一个连接。开启 WAL 模式（`PRAGMA journal_mode=WAL`），读不阻塞写 |
| 日志文件 | `LogManager` 内部使用 `QMutex`，可跨线程安全调用 |
| 配置文件 | `ConfigManager` 内部使用 `QMutex`，启动时读取后缓存，非频繁操作 |
| DataManager | 主线程独占，工作线程通过信号/槽间接请求（重 I/O 场景） |

## 6. 关键数据流

### 6.1 电脑端本地记录（通过 ReportService）

```
用户输入 "完成需求文档" → 点击提交
  │
  ▼
FloatingInputViewModel::submitRecord()
  │
  ├─ 调用 ReportService::addRecord(year, month, day, content)
  │     │
  │     ├─ 生成时间戳 QTime::currentTime().toString("HH:mm")
  │     └─ 调用 DataManager::addRecord(year, month, day, time, content)
  │           │
  │           ├─ FileManager::readDailyFile()
  │           ├─ 追加 + 排序
  │           ├─ 乐观锁写入（.tmp → 事务 → rename）
  │           ├─ 成功 → 返回 Success
  │           └─ 冲突 → 返回 VersionConflict
  │
  ├─ Success → emit recordSubmitted() → QML 清空 + ✓
  └─ VersionConflict → emit submitFailed("保存失败，请重试")
```

> **架构要点**：ViewModel 不知道 DataManager 的存在。它只调 `ReportService::addRecord()`，ReportService 内部调 DataManager。

### 6.2 手机端同步提交 (/sync/submit)

```
HttpServer::handleSubmit(QHttpServerRequest)
  │
  ├─ 提取 Header: X-Batch-ID
  ├─ 读取 Body → QString text
  │
  ▼
SyncService::submit(text, batchId)
  │
  ├─ DatabaseManager::isBatchProcessed(batchId)
  │     └─ true → 跳到 generateIndex 返回 code=0（幂等）
  │
  ├─ parseSubmitBody(text)
  │     └─ 按 \n\n\n 分割日期块 → QMap<QDate, QList<DailyRecord>>
  │
  ├─ DataManager::mergeRecords(recordsByDate, batchId)
  │     │
  │     └─ 对每个日期：
  │           ├─ FileManager::readDailyFile()
  │           ├─ 合并 + 排序
  │           ├─ 写入 .tmp
  │           ├─ DatabaseManager::updateWithVersion()
  │           │     └─ 冲突 → 回滚 + 删 .tmp → ErrorCode::VersionConflict
  │           └─ DatabaseManager::insertBatch()
  │
  ├─ 成功 → rename(.tmp → .txt)
  │         → emit dataChanged()
  │         → 构造 updated_index JSON
  │         → 返回 { code: 0, ... }
  │
  └─ 版本冲突 → 返回 { code: -4, message: "..." }
```

### 6.3 启动恢复流程

```
main.cpp → AppCore::init()
  │
  ├─ 0. LogManager::init("logs/")
  ├─ 1. ConfigManager::load()
  ├─ 2. DatabaseManager::open("just_do.db")
  │       └── migrate() → CREATE TABLE IF NOT EXISTS
  │       └── PRAGMA journal_mode=WAL
  │
  ├─ 3. FileManager::recoverTmpFiles()
  │       └── 扫描 data/**/ *.tmp
  │           ├─ 无 .tmp → 继续
  │           └─ 有 .tmp → rename(.tmp → .txt) + 日志记录
  │
  ├─ 4. DataManager 就绪
  ├─ 5. SyncService 就绪
  ├─ 6. ConnectionStateMachine → 未启动
  ├─ 7. HttpServer 就绪
  │
  └─ 8. emit startupCompleted()
        └── QML 引擎加载 main.qml
```

### 6.4 连接建立 + 心跳

```
手机端扫 QR 码 → 调用 POST /sync/connect
  │
  ▼
HttpServer::handleConnect()
  ├─ ConnectionStateMachine::onConnect()
  │     └── mState = Connected
  │     └── emit stateChanged(Disconnected, Connected)
  │           └── ConnectionViewModel 更新 → QML StatusBar 刷新
  └─ 返回 { code: 0, server_info: {...} }


手机端定时 GET /health（每 15s）
  │
  ▼
HttpServer::handleHealth()
  ├─ ConnectionStateMachine::onHeartbeatReceived()
  │     └── mHeartbeatTimer.start(45000)   // 重置 45s 定时器
  └─ 返回 { status: "ok", timestamp: "..." }


45 秒超时（mHeartbeatTimer.timeout()）
  └── ConnectionStateMachine
        ├── mState = Disconnected
        └── emit stateChanged(Connected, Disconnected)
```

## 9. 错误处理与日志策略

### 错误传播

```
底层 (FileManager, DatabaseManager)
  │  返回 bool / ErrorCode / std::optional
  │
  ▼
中层 (DataManager, SyncService)
  │  转换 ErrorCode + 调用 LogManager
  │
  ▼
上层 (ViewModel)
  │  ErrorCode → QString message → Q_PROPERTY / 信号 → QML 显示
```

### 日志级别使用规范

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| DEBUG | 开发调试信息 | "读取文件 data/2026/07/23.txt, 3 条记录" |
| INFO | 关键操作记录 | "HTTP 服务启动, 端口 18080" |
| WARN | 可恢复的异常 | "版本冲突, 日期 2026-07-23, 稍后重试" |
| ERROR | 不可恢复的错误 | ".tmp 写入失败, 磁盘满?" |

### 各模块日志要点

| 模块 | 需记录的关键事件 |
|------|----------------|
| AppCore | 启动/关闭、各模块初始化结果 |
| HttpServer | 启动监听、接收请求、响应状态码 |
| SyncService | 批次处理 (batch_id, 日期数)、解析错误 |
| DataManager | 文件读写、索引更新、乐观锁冲突 |
| FileManager | .tmp 恢复、rename 操作 |
| ConnectionStateMachine | 状态转移 |
