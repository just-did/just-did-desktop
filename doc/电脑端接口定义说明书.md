# 电脑端接口定义（PC API Specification）

> 版本：v1.1
> 最后更新：2026-07-23

电脑端提供四个 HTTP 接口，供手机端调用，均通过局域网访问。

---

## 接口 1：建立连接

**功能**：手机端扫码后调用此接口，与电脑端建立连接。

- **URL**：`/sync/connect`
- **方法**：`POST`
- **Content-Type**：`application/json`

### 请求体
```json
{
  "device_name": "iPhone"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| device_name | string | 手机端设备名称，仅用于显示 |

### 响应（HTTP 200）
```json
{
  "code": 0,
  "message": "连接成功",
  "server_info": {
    "version": "1.0.0",
    "hostname": "MyPC"
  }
}
```

> 成功后电脑端连接状态从"未连接"转移至"已连接"。已连接状态下重复调用返回 `code=0`（幂等）。

---

## 接口 2：健康检查

**功能**：手机端定时发送心跳，电脑端被动接收以维持连接状态。

- **URL**：`/health`
- **方法**：`GET`

### 响应（HTTP 200）
```json
{
  "status": "ok",
  "timestamp": "2026-07-23T10:30:00"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| status | string | 固定为 `"ok"` |
| timestamp | string | ISO 8601 格式的服务器当前时间 |

> **心跳参数**（不可配置）：手机端每 **15 秒** 发送一次心跳；电脑端 **45 秒** 内未收到心跳判定断连，状态自动回到"未连接"。断连不影响已持久化数据。

---

## 接口 3：辅端数据提交接口

**功能**：接收手机端暂存文件内容，合并入电脑端日报文件，并返回被修改文件的索引列表（不含文件内容）。

- **URL**：`/sync/submit`
- **方法**：`POST`
- **Content-Type**：`text/plain; charset=utf-8`
- **请求头**：`X-Batch-ID: {UUID}`（必填）

### 请求体格式

手机端 `staging.txt` 的原始文本内容（UTF‑8）。格式规则：

- 日期块之间用 `\n\n\n`（三个换行）分隔
- 每个日期块首行为日期（`YYYYMMDD`）
- 块内记录用 `\n\n`（两个换行）分隔
- 每条记录内部，时间与内容用第一个 `\n` 分隔

**示例**（展示用 `\n` 转义）：
```
20260723\n09:54\n完成需求文档初稿\n\n10:30\n参加项目评审会议\n\n\n20260724\n14:00\n修复登录页面样式问题\n\n16:30\n与后端联调接口
```

**可视化**（实际文本的样子）：
```
20260723
09:54
完成需求文档初稿

10:30
参加项目评审会议

20260724
14:00
修复登录页面样式问题

16:30
与后端联调接口
```

### 电脑端处理逻辑

1. 从请求 Header `X-Batch-ID` 获取批次ID。
2. 查询 `pc_processed_batches` 表，检查该批次ID是否已存在：
   - **若存在**：跳过合并，直接跳到步骤7生成 `updated_index`，返回 `code=0`（幂等：数据已在上次请求中成功合并）。
   - **若不存在**：继续以下步骤。
3. 解析请求体文本：
   - 按 `\n\n\n` 分割得到日期块。
   - 每个块第一行为日期（`YYYYMMDD`），余下部分按 `\n\n` 分割得到记录。
   - 每条记录按第一个 `\n` 拆分为 `时间`（`HH:MM`）和 `内容`。
4. 按日期分组，对每个日期：
   - 构建文件路径：`data/{YYYY}/{MM}/{DD}.txt`（注意补零）。
   - 读取原文件（若存在），将属于该日期的记录追加到末尾。
   - 追加完成后，读取整个文件，按时间递增排序，生成完整新内容。
   - 记录当前索引中的 `version` 值（乐观锁）。
5. 开启 SQLite 事务，对每个日期：
   - 将完整新内容写入临时文件 `{目标文件名}.tmp`。
   - 验证写入成功。
   - 使用乐观锁更新索引：`UPDATE pc_daliy_report_index SET file_size=?, version=version+1 WHERE year=? AND month=? AND day=? AND version=?`
   - 若 `affected rows = 0`（版本冲突），**回滚事务**，删除所有 `.tmp` 文件，返回 `code=-4`。
   - 若任一临时文件写入失败：**回滚事务**，删除所有 `.tmp` 文件，返回 `code=1`。
6. 所有临时文件写入成功后：
   - 在事务中插入 `pc_processed_batches` 记录（batch_id + 受影响日期列表，逗号分隔）。
   - 提交事务。
   - 执行 `rename(.tmp → 目标文件)` 原子替换。
7. 从 `pc_processed_batches` 读取该批次的 `dates` 列表，查询 `pc_daliy_report_index` 获取各日期的 `path` 和 `file_size`，生成 `updated_index`。

### 响应格式（JSON）

- **成功**（HTTP 200）：
  ```json
  {
    "code": 0,
    "message": "暂存提交成功",
    "updated_index": [
      {
        "year": 2027,
        "month": 7,
        "day": 21,
        "path": "2027/07/21.txt",
        "file_size": 256
      }
    ]
  }
  ```
  > 无论首次合并还是批次已处理（幂等），均返回 `code=0` 并包含 `updated_index`。

- **版本冲突**（HTTP 409）：
  ```json
  {
    "code": -4,
    "message": "数据版本冲突，请重试"
  }
  ```
  > 手机端收到此错误应稍后重试整个请求。

- **存储错误**（HTTP 500）：
  ```json
  {
    "code": 1,
    "message": "服务器存储错误"
  }
  ```

- **内部错误**（HTTP 500）：
  ```json
  {
    "code": -1,
    "message": "错误描述"
  }
  ```

> `updated_index` 数组元素字段与电脑端表结构一致，无 `status`。

## 接口 4：日报拉取接口

**功能**：根据请求的日期范围或列表，返回一个或多个日报文件的完整内容（单文件返回文本，多文件返回 ZIP 压缩包）。

- **URL**：`/sync/fetch`
- **方法**：`POST`
- **Content-Type**：`application/json`

### 请求体（二选一）

```json
{ "dates": ["20270721", "20270722"] }
```
或
```json
{ "start": "20270701", "end": "20270731" }
```

| 参数 | 类型 | 说明 |
|------|------|------|
| dates | string[] | 具体日期列表，最多 32 个 |
| start | string | 闭区间起始日期（含） |
| end | string | 闭区间结束日期（含），`end - start ≤ 31` 天 |

> 若同时提供两者，优先使用 `dates`。

### 限制与错误

- 请求的文件总数不得超过 **32 个**。超出 → HTTP 400，`code=-2`。
- 区间跨度不得超过 **31 天**。超出 → HTTP 400，`code=-3`。
- 未提供任何日期参数 → HTTP 400，`code=-3`。

### 电脑端处理逻辑

1. 根据请求的日期列表或区间，查询 `pc_daliy_report_index` 索引表。
2. 根据索引中的 `path` 检查对应日报文件是否存在。
3. 按文件个数返回结果。

### 电脑端响应

- **单文件**（仅请求1个日期）：
  - 文件存在 → HTTP 200，`Content-Type: text/plain; charset=utf-8`，Body 为文件完整文本。
  - 文件不存在 → HTTP 404，Body 为 JSON 错误体 `{"code":-1,"message":"文件不存在"}`。
- **多文件**（请求 ≥2 个日期）：
  - 至少有一个文件存在 → HTTP 200，`Content-Type: application/zip`，ZIP 内保持 `data/YYYY/MM/DD.txt` 目录结构。
  - 所有文件均不存在 → HTTP 404。
  - ZIP 包中仅包含存在的文件，不存在的日期自动忽略。

### 手机端处理建议

- 单文件：直接写入本地对应路径（覆盖）。
- ZIP：解压到本地 `data/` 目录（覆盖已有的同名文件）。
- 成功写入后，将对应日期的 `status` 更新为 `1`（手机端本地操作）。

---

## 错误码汇总

| code | HTTP 状态码 | 含义 |
|------|------------|------|
| 0 | 200 | 成功（含首次合并与幂等返回） |
| 1 | 500 | 服务器存储错误（文件写入失败） |
| -1 | 500 | 服务器内部错误或解析失败 |
| -2 | 400 | 请求文件数超限 |
| -3 | 400 | 请求参数无效（如日期格式错误） |
| -4 | 409 | 数据版本冲突（乐观锁），需重试 |
