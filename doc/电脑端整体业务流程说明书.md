# 电脑端整体业务流程说明书

> 版本：v1.1
> 最后更新：2026-07-23
> 整合来源：需求文档、数据定义说明书、接口定义说明书、数据一致性方案说明书、状态机图、原型图

电脑端是系统的**唯一权威数据源**，承担三个核心职责：
1. **本地记录**：通过悬浮窗或管理界面记录日常事务
2. **HTTP 服务**：为手机端提供数据提交和拉取接口
3. **全量存储**：所有日报文件的最终归属地

---

## 1. 电脑端架构

```
┌──────────────────────────────────────────┐
│              电脑端（主端）               │
│                                          │
│  ┌──────────┐  ┌──────────────────┐     │
│  │ 悬浮输入窗 │  │   完整管理界面     │     │
│  │ (仅记录)  │  │  (日报查看+管理)   │     │
│  └────┬─────┘  └────────┬─────────┘     │
│       │                 │                │
│       └────────┬────────┘                │
│                ▼                         │
│  ┌──────────────────────────┐           │
│  │       本地存储             │           │
│  │  data/YYYY/MM/DD.txt     │           │
│  │  just_do.db (索引)        │           │
│  └────────────┬─────────────┘           │
│               │                          │
│  ┌────────────┴─────────────┐           │
│  │       HTTP 服务端         │           │
│  │  POST /sync/connect      │◄── 手机端  │
│  │  GET  /health            │◄── 手机端  │
│  │  POST /sync/submit       │◄── 手机端  │
│  │  POST /sync/fetch        │──► 手机端  │
│  └──────────────────────────┘           │
│                                          │
│  权威数据源 · 全量存储 · 二维码生成        │
└──────────────────────────────────────────┘
```

**技术栈**：C++ / Qt

三层结构：UI 层（悬浮窗 + 管理界面）→ 服务层（HTTP 服务 + 文件管理 + 状态机）→ 数据层（SQLite + 文件读写）。

## 2. 流程一：电脑端记录

```
用户操作                      系统行为
────────                    ────────
打开悬浮窗/管理界面
  │
  ├─ 输入内容并提交
  │        │
  │        ▼
  │   获取当前时间戳 (HH:MM)
  │        │
  │        ▼
  │   定位今日日报文件
  │   data/{YYYY}/{MM}/{DD}.txt
  │        │
  │        ├─ 文件存在 ──► 读取文件 + 获取索引 version（乐观锁）
  │        │
  │        └─ 文件不存在 ──► 创建目录 + 空文件，追加
  │        │
  │        ▼
  │   追加新记录 + 全文按时间排序
  │        │
  │        ▼
  │   乐观锁写入：
  │   UPDATE pc_daliy_report_index
  │   SET file_size=?, version=version+1
  │   WHERE year=? AND month=? AND day=? AND version=?
  │        │
  │        ├─ 版本匹配 → 写入 .tmp → 提交事务 → rename → 成功
  │        │
  │        └─ 版本冲突 → 回滚 → 提示"保存失败，请重试"
  │        │
  │        ▼
  │   输入框清空，待下次输入
```

**特点**：无需网络，本地直接写入。使用乐观锁防止与手机端同步发生并发写入冲突。每次追加后全文排序，索引同步更新。

## 3. 流程二：处理手机端同步请求

电脑端提供四个 HTTP 接口供手机端调用。

### 3.1 建立连接（POST /sync/connect）

```
电脑端处理
──────────
1. 解析请求体：{"device_name": "iPhone"}

2. 记录设备名称（用于界面显示）

3. 状态转移：未连接 → 已连接

4. 返回 { code: 0, message: "连接成功", server_info: {...} }

注：已连接状态下重复调用返回 code=0（幂等）
```

### 3.2 健康检查（GET /health）

```
电脑端处理
──────────
1. 接收请求，更新"最近心跳时间"为当前时间

2. 返回 { status: "ok", timestamp: "..." }

注：手机端每 15 秒发送一次心跳。
    电脑端 45 秒内未收到心跳 → 状态转移：已连接 → 未连接。
    断连不影响已持久化数据，仅停止接收新的同步请求。
```

### 3.3 接收暂存提交（POST /sync/submit）

```
电脑端处理
──────────
1. 从 Header 获取 X-Batch-ID

2. 查 pc_processed_batches
   batch_id 是否存在？
   ├─ 存在 → 跳过合并，跳到步骤 7
   │         （幂等：数据已在上次请求中成功合并）
   │
   └─ 不存在 → 继续

3. 解析请求体文本：
   • 按 \n\n\n 分割日期块
   • 每块首行为日期 (YYYYMMDD)
   • 块内按 \n\n 分割记录
   • 每条记录按第一个 \n 拆分为时间和内容

4. 按日期分组：
   • 构建目标文件路径 data/{YYYY}/{MM}/{DD}.txt
   • 读取原文件（若存在）+ 获取当前 version
   • 追加新记录并排序
   • 生成完整新内容

5. 开启 SQLite 事务，对每个日期：
   • 写入临时文件 .tmp
   • 验证写入成功
   • 乐观锁更新索引：
     UPDATE pc_daliy_report_index
     SET file_size=?, version=version+1
     WHERE year=? AND month=? AND day=? AND version=?
   ├─ affected rows = 0 → 版本冲突！
   │   回滚事务 + 删除 .tmp → 返回 { code: -4, message: "数据版本冲突，请重试" }
   │
   ├─ 全部成功 → 继续
   │
   └─ 任一 .tmp 写入失败 →
       回滚事务，删除所有 .tmp
       返回 { code: 1, message: "服务器存储错误" }

6. INSERT pc_processed_batches (batch_id, dates)
   dates 格式：逗号分隔，如 "20260723,20260724"
   提交事务
   rename(.tmp → 目标文件)

7. 生成 updated_index：
   • 从 pc_processed_batches 读该 batch 的 dates 列表
   • 查 pc_daliy_report_index 取各日期的 path 和 file_size

8. 返回 { code: 0, message: "暂存提交成功", updated_index: [...] }
```

### 3.4 响应日报拉取（POST /sync/fetch）

```
电脑端处理
──────────
1. 解析请求体：
   • dates: ["20260721", "20260722"]     ← 具体日期列表（最多 32 个）
   • 或 { start: "20260701", end: "20260731" }  ← 闭区间（≤ 31 天）

2. 按日期查询 pc_daliy_report_index
   根据索引中的 path 检查文件是否存在

3. 按文件个数返回：
   ├─ 1 个且有 → Content-Type: text/plain
   ├─ ≥2 个且有 → Content-Type: application/zip
   │              ZIP 内保持 data/YYYY/MM/DD.txt 目录结构
   └─ 全部无 → HTTP 404
```

**限制**：单次请求文件总数 ≤ 32 个。

## 4. 流程三：连接管理

### 4.1 电脑端连接状态机

```
                ┌──────────┐
                │  未启动   │
                └────┬─────┘
                     │ 用户点击"启动"，HTTP 服务开始监听
                     ▼
                ┌──────────┐
          ┌────►│  未连接   │◄──────────────┐
          │     └────┬─────┘               │
          │          │ 手机端调用            │
          │          │ POST /sync/connect   │
          │          ▼                     │
          │     ┌──────────┐               │
          │     │  已连接   │───────────────┘
          │     └────┬─────┘  45 秒未收到
          │          │         GET /health
          │          │         （自动断连）
          │          │ 手机端调用
          │          │ POST /sync/submit
          │          ▼
          │     ┌──────────┐
          │     │  同步中   │
          │     └────┬─────┘
          │          │ 同步完成
          └──────────┘
```

| 状态转移 | 触发条件 |
|---------|---------|
| 未启动 → 未连接 | 用户点击"启动"，HTTP 服务开始监听，默认端口 18080 |
| 未连接 → 已连接 | 手机端调用 `POST /sync/connect` |
| 已连接 → 同步中 | 手机端调用 `POST /sync/submit` |
| 同步中 → 已连接 | 同步流程完成 |
| 已连接 → 未连接 | 45 秒内未收到 `GET /health` 心跳 |
| 未连接 → 未启动 | 用户关闭 HTTP 服务 |

### 4.2 QR 码与连接流程

```
电脑端启动 HTTP 服务
  │
  ├─ 获取局域网 IP（优先以太网，其次 WiFi）
  ├─ 在管理界面生成二维码，内容为 http://{IP}:{port}
  │
  └─ 手机端扫码 → 解析出地址 → 调用 POST /sync/connect
       │
       └─ 电脑端收到 → 状态转移至"已连接" → 界面更新状态显示
```

### 4.3 健康检查参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 手机端心跳间隔 | 15 秒 | 手机端定时调 `GET /health` |
| 电脑端超时阈值 | 45 秒 | 可在 config.yml 中修改 |

## 5. 流程四：启动异常恢复

```
电脑端启动
  │
  ├─ 扫描 data/ 目录下所有 .tmp 文件
  │     │
  │     ├─ 无 .tmp 文件 ──► 正常启动
  │     │
  │     └─ 存在 .tmp 文件 ──► 执行 rename(.tmp → 目标文件)
  │                          正常启动
```

**原理**：`.tmp` 文件存在说明上一次写入在 rename 前崩溃。事务已提交（`pc_processed_batches` 已记录），手机端重试时走幂等路径（code=0），不会重复合并。启动时直接 rename 恢复即可。

---

## 6. 流程五：数据一致性保障（电脑端职责）

| 机制 | 实现 |
|------|------|
| **幂等性** | `pc_processed_batches` 表以 `batch_id` 为主键，同一批次只处理一次。已处理的批次返回 code=0 + updated_index |
| **原子写入** | 先写 `.tmp` 完整内容 → SQLite 事务提交 → `rename(.tmp → 目标)`，防止写入中途崩溃损坏文件 |
| **事务性** | SQLite 事务包裹 batch_id 插入 + 索引更新，全部成功或全部回滚。写入失败 → 回滚 + 删除 .tmp + 返回 code=1 |
| **乐观锁** | `pc_daliy_report_index.version` 字段，读写时校验版本号。版本冲突返回 code=-4，由调用方重试 |
| **启动恢复** | 启动时扫描 `.tmp` 文件，若存在则 rename 恢复 |

## 7. 流程六：查看日报

```
用户操作                      系统行为
────────                    ────────
打开管理界面
  │
  ├─ 界面加载时：
  │   仅读取 pc_daliy_report_index 索引表
  │   渲染日历视图（标记哪些日期有日报）
  │   不加载任何 .txt 文件内容
  │
  ├─ 点击某个日期：
  │   查索引获取路径 → 读取 .txt → 解析渲染为时间线
  │
  ├─ 翻月（"<" / ">"）：
  │   按月份区间查索引 → 刷新日历标记 → 不自动加载内容
  │
  └─ 日历组件右上角 [加载/清空] 模式切换：
      ├─ 加载模式：勾选日期 → "加载已选" → 读取本地文件渲染
      └─ 清空模式：勾选日期 → "清空已选" → 删除本地文件（危险操作）
```

**关键设计**：索引与内容分离——日历只查索引，点击日期才读 .txt。避免一次性加载全部内容。

**删除粒度**：仅支持按天清空，不支持单条记录的编辑或删除。清空操作同时删除 .txt 文件和索引条目。

## 8. 流程七：存储管理

```
打开存储管理界面
  │
  ├─ 查看存储概览
  │   • 总占用空间 / 按年月分类统计
  │
  ├─ 清理旧数据
  │   • 按时间段选择 → 删除 .txt 文件 + 索引条目 + 空目录
  │
  ├─ 备份数据
  │   • 导出指定时间段日报 → 打包为 ZIP（含目录结构）
  │   • 文件命名：backup_{YYYYMMDD}_{HHmmss}.zip
  │
  └─ 恢复数据
      • 选择 ZIP → 解压到 data/ → 重建索引
```

电脑端没有存储上限，用户自行管理磁盘空间。

## 9. 流程八：悬浮窗交互

```
电脑端主窗口最小化/关闭到托盘
  │
  ▼
悬浮窗显示（屏幕右侧，置顶）
  │
  ├─ 状态：未激活（缩起状态，仅显示 "刚刚做了什么？" 标题）
  │     │
  │     └─ 单击 → 切换为激活状态（展开输入区域）
  │
  ├─ 状态：激活（展开状态，显示输入框 + 提交按钮）
  │     │
  │     ├─ 单击空白处 → 切换为未激活状态（收起）
  │     ├─ 输入内容 + 提交 → 走流程一（电脑端记录）
  │     └─ 双击 → 显示主窗口（管理界面）
  │
  └─ 主窗口打开时，悬浮窗自动隐藏
```

## 10. 流程九：日志系统

```
应用运行期间
  │
  ├─ 所有模块通过统一的日志管理器输出日志
  │   • 格式：[YYYY-MM-DD HH:MM:SS] [LEVEL] message
  │   • 级别：DEBUG / INFO / WARN / ERROR
  │
  ├─ 写入 logs/just-did.log
  │     │
  │     └─ 文件达到 4MB → 滚动
  │           just-did.log → just-did.1.log
  │           just-did.1.log → just-did.2.log
  │           新建 just-did.log 继续写入
  │
  └─ 滚动后检查总大小
        │
        └─ 超过 12MB → 删除最旧的日志文件（just-did.2.log）
```

## 11. 业务规则汇总

| 规则 | 说明 |
|------|------|
| 技术栈 | C++ / Qt |
| HTTP 端口 | 默认 18080，可在 config.yml 中修改 |
| 记录格式 | `HH:MM\n内容`，`\n\n` 分隔记录，内容中禁止 `\n\n` |
| 操作粒度 | 仅支持按天追加和按天清空，不支持单条编辑/删除 |
| 时间排序 | 文件内记录按时间递增排列 |
| 文件路径 | `data/{YYYY}/{MM}/{DD}.txt`，月日两位补零 |
| HTTP 接口 | `/sync/connect`（连接）、`/health`（心跳）、`/sync/submit`（提交）、`/sync/fetch`（拉取） |
| 拉取上限 | 单次最多 32 个日期，区间跨度 ≤ 31 天 |
| 二维码 | 生成 `http://{局域网IP}:{端口}` 供手机端扫码 |
| 健康检查 | 手机端每 15s 发心跳，电脑端 45s 未收到判定断连 |
| 幂等保证 | `pc_processed_batches` 表 + batch_id (UUID) 唯一索引 |
| 原子写入 | `.tmp` 完整写入 → 事务提交 → `rename` 覆盖 |
| 乐观锁 | `pc_daliy_report_index.version` 字段，冲突返回 code=-4 |
| 启动恢复 | 扫描 `.tmp` 文件 → `rename` 恢复 |
| 响应码 | 0=成功, 1=存储错误, -1=内部错误, -2=超限, -3=参数无效, -4=版本冲突 |
| 索引表 | `pc_daliy_report_index`：year/month/day/path/file_size/version |
| 日历加载 | 仅查索引不读 txt，点击具体日期才加载内容 |
| 配置持久化 | config.yml（YAML），缺失时使用默认值 |
| 日志 | 文件滚动存储，单文件 4MB，总上限 12MB |
| 安全 | 暂不考虑认证机制，仅局域网使用 |
| 多设备 | 暂仅支持单台手机连接 |
| 搜索 | 本次不做 |
