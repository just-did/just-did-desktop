# 电脑端数据定义（PC Data Definition）

> 版本：v1.1
> 最后更新：2026-07-23

## 1. 目录结构（电脑端）

```
电脑根目录/
├── data/                               # 所有日报文件（权威数据源）
│   ├── 2026/
│   │   ├── 07/
│   │   │   ├── 21.txt
│   │   │   └── 22.txt
│   │   └── 08/
│   └── 2027/
│       └── 07/
│           └── 21.txt
├── logs/                               # 运行日志
│   ├── just-did.log                    # 当前日志文件
│   ├── just-did.1.log                  # 滚动日志文件
│   └── just-did.2.log                  # 滚动日志文件
├── just_do.db                          # SQLite 索引数据库
└── config.yml                          # 配置文件
```

> 电脑端**不包含** `staging.txt`，所有临时数据由手机端管理。

## 2. 日报文件（`日.txt`）格式

> 与手机端完全一致。

- **编码**：UTF‑8
- **时间格式**：`HH:MM`（24小时制，两位数，如 `09:54`）
- **单条记录**：`时间\n内容`（一个换行分隔）
- **记录分隔**：`\n\n`（两个换行，内容中禁止出现）
- **排序**：按时间**递增**（早在上，晚在下）
- **文件路径**：`data/{YYYY}/{MM}/{DD}.txt`（例：`data/2027/07/21.txt`）
- **操作粒度**：仅支持按天追加和按天清空，不支持单条记录的编辑或删除

## 3. 电脑端 SQLite 索引表（`just_do.db`）

### 3.1 日历索引表

- **表名**：`pc_daliy_report_index`
- **建表语句**：

```sql
CREATE TABLE IF NOT EXISTS pc_daliy_report_index (
    year INTEGER NOT NULL,
    month INTEGER NOT NULL,
    day INTEGER NOT NULL,
    path TEXT NOT NULL,
    file_size INTEGER NOT NULL,
    version INTEGER NOT NULL DEFAULT 1,
    PRIMARY KEY (year, month, day)
);
```

- **字段说明**：

| 字段 | 说明 |
|------|------|
| year / month / day | 日期主键 |
| path | 日报文件相对路径（如 `2027/07/21.txt`） |
| file_size | 文件字节数，每次写入后更新 |
| version | 乐观锁版本号，每次写入成功后 +1。读取时记录版本，写入时校验版本未变 |

> 电脑端索引仅用于快速查找文件路径和大小，**无 `status` 字段**（与手机端不同），不涉及完整性状态。

### 3.2 幂等批处理记录表

- **表名**：`pc_processed_batches`
- **建表语句**：

```sql
CREATE TABLE IF NOT EXISTS pc_processed_batches (
    batch_id TEXT PRIMARY KEY,
    dates TEXT NOT NULL
);
```

- **字段说明**：

| 字段 | 说明 |
|------|------|
| batch_id | UUID，来自请求 Header `X-Batch-ID`，唯一索引 |
| dates | 受影响的日期列表，**逗号分隔**，格式如 `20260723,20260724` |

## 4. 数据存储与维护规则

- **文件创建**：当手机端提交暂存记录时，若对应日期文件不存在，电脑端自动创建。
- **记录追加与排序**：
  - 接收暂存记录后，按日期分组。
  - 对每个日期，将新记录追加到该日文件末尾（确保末尾有换行）。
  - 追加完成后，对整个文件按时间（`HH:MM`）递增排序，重写文件。
- **文件大小更新**：每次修改后，计算文件字节数，并在索引表中更新 `file_size`。
- **索引同步**：电脑端索引在每次修改文件后立即更新（`INSERT OR REPLACE`），保证与文件系统一致。

### 4.1 乐观锁并发控制

电脑端本地记录和手机端同步可能同时修改同一日期的文件。采用乐观锁防止丢失写入：

```
1. 读取当前文件内容 + 从 pc_daliy_report_index 获取 version
2. 构建新内容（追加记录 + 排序）
3. 开启 SQLite 事务
4. UPDATE pc_daliy_report_index
   SET file_size = ?, version = version + 1
   WHERE year = ? AND month = ? AND day = ? AND version = ?
5. 若 affected rows = 0（版本已变）→ 回滚，删除 .tmp，返回冲突错误
6. 若 affected rows = 1 → 写入 .tmp → 提交事务 → rename(.tmp → 目标文件)
```

冲突时由调用方决定是否重试（手机端可稍后重试 `/sync/submit`；本地记录可提示用户"保存失败，请重试"）。

## 5. 日志文件规范

- **存放目录**：`{app-root}/logs/`
- **文件命名**：`just-did.log`（当前）、`just-did.1.log`、`just-did.2.log`（历史滚动）
- **单文件上限**：4 MB
- **总容量上限**：12 MB（3 个文件 × 4 MB）
- **滚动策略**：
  - 当前文件达到 4 MB → 重命名为 `just-did.1.log`，原 `just-did.1.log` → `just-did.2.log`，新建 `just-did.log`
  - 若滚动后总大小超过 12 MB → 删除 `just-did.2.log`
- **日志格式**：`[YYYY-MM-DD HH:MM:SS] [LEVEL] message`
- **日志级别**：DEBUG / INFO / WARN / ERROR

## 6. 配置文件规范（`config.yml`）

- **路径**：`{app-root}/config.yml`
- **格式**：YAML
- **示例**：

```yaml
# 网络配置
server:
  port: 18080               # HTTP 服务端口，默认 18080
  heartbeat_timeout: 45     # 心跳超时阈值（秒），超时未收到心跳判定断连

# 窗口配置
ui:
  floating_window:
    x: 100                  # 悬浮窗上次关闭时的 X 坐标
    y: 200                  # 悬浮窗上次关闭时的 Y 坐标
  main_window:
    width: 800
    height: 600
```

- 配置文件缺失时使用默认值，首次启动自动生成。

## 7. 备份文件规范

- **导出格式**：ZIP 压缩包
- **文件命名**：`backup_{YYYYMMDD}_{HHmmss}.zip`（如 `backup_20260723_143052.zip`）
- **内部结构**：保持 `data/YYYY/MM/DD.txt` 目录结构
